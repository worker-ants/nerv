0.3 우선순위

사람과 에이전트가 읽는 곳이 먼저다 — 화면 문구(packages/schema/src/i18n/ko.ts) · 제품 매뉴얼 · 플러그인 스킬. 명세 md 와 html 파생본은 그 뒤에 따라온다. 스킬은 문서가 아니라 모델이 읽는 규약이라 화면과 같은 무게로 다룬다(AGENTS.md 구현 규약 6).

📐
"판" 과 "버전" 을 가른 이유

전수 315곳 중 29곳이 버전이 아니라 판본이었고, 가장 분명한 증거는 모든 문서의 머리글이다 — > 문서 버전 v0.3 · 2026-09-05 · HTML 판: [...] 은 한 줄 안에 둘이 함께 있고 서로 다른 것을 가리킨다. 일괄 치환하면 "문서 버전 … HTML 버전:" 이 되어 뒤엣것이 무엇인지 알 수 없어진다. 그래서 버전 뜻 286곳만 옮기고, 판본 뜻은 "HTML 파생본" 으로 바꿨다 — 이 저장소가 이미 md 를 원본, html 을 파생본이라 부르기 때문이다.

"고정 ID" 와 화면의 "번호". "안정" 은 한국어에서 흔들리지 않는 상태를 뜻해, 실제 뜻인 "옮겨도 변하지 않는 값" 이 이름에서 오지 않았다. 문서가 그 뜻을 매번 다시 설명하던 것이 증거다(database.md: "안정 ID. 이동·개명해도 참조 불변"). 화면에서는 "번호" 로 충분하다 — 사람은 SPC-… 를 이미 번호로 읽는다. "고정 ID" 는 스펙·요구사항·작업을 아울러야 하는 명세의 개념어다.

3.2 왜 규칙이 필요했나

규정이 저장소 어디에도 없었다 — docs/·매뉴얼·AGENTS.md·카탈로그 머리 주석 모두. 카탈로그는 규칙 셋(키 짓기·자리표시자·식별자 비번역)을 적어 두었는데 말투만 빠져 있었고, 그래서 설명·근거를 적는 문장이 문서의 말투를 그대로 끌고 들어왔다. 자국은 화면 아홉이었고, 의도가 아니라는 근거는 넷이다.

  1. 같은 슬롯의 다수가 반대편이다. 흐린 주석 자리(faint·mute·hint·title)의 한국어 153건 중 합쇼체 67 · 해라체 8. 주석의 말투였다면 이 비가 나오지 않는다.
  2. 같은 컴포넌트 안에서 갈렸다. resolve-dialog.tsx 의 Field hint 셋 중 둘만 해라체였고, ko.ts 의 나란한 두 줄이 '요구사항은 그대로다' / '본문이 같습니다.' 였다(같은 diff 뷰의 같은 자리).
  3. 영문과 상관관계가 없다. 해라체 여덟 중 여섯의 영문이 이웃과 같은 문장형(대문자+마침표)이었고, 반대로 합쇼체인 reviews.resolve.spec_hint 의 영문은 소문자·마침표 없음이었다. 두 언어가 함께 지키는 규칙이 아니었다.
  4. 도입 커밋이 스스로 섞였다. 카탈로그를 만든 커밋(06ec9fca — i18n 전면 적용)이 그 한 커밋에서 합쇼체 176 · 해라체 7 을 함께 넣었다. 규칙이었다면 그 커밋이 지켰다.

3.3 고치지 않은 셋

import.requirement_not_found · import.task_not_found 는 웹이 그리지 않는다 — apps/cli/src/run.ts 가 item.detail ?? t('cli.reason.load_failed') 로 소비하므로 cli.reason.* 열아홉과 같은 자리다. export.index_lead 는 llms.txt 에 쓰이는 문서 본문이다. 셋 다 §3.1 의 규칙대로 해라체가 맞다.

4. 적용 규칙

4.1 일괄 치환이 안 되는 넷

낱말박혀 있는 곳거르는 법
리스릴리스 · 리스트 · 휴리스틱앞의 릴·휴, 뒤의 트·틱 을 배제한다. 배제 전 950건 → 후 796건
워크플로워크플로우 의 앞부분뒤에 우 가 오지 않는 것만 고른다
판판단 · 판정 · 판별 · 재판 · 출판앞뒤가 한글이 아니거나 조사가 붙은 것만 고른다. 그러고도 판본 뜻이 남으므로 §2.2 를 함께 본다
클레임—바꾸는 것은 status.task.claimed 한 칸이다. 나머지 944곳은 그대로 둔다

측정에서 생성물은 뺀다 — .tsbuild·dist·node_modules. 넣고 세면 몇 건씩 부푼다.

4.2 규약이 요구하는 동반 변경

  1. md 와 html 은 같은 커밋에서(README 관리 규약 1). 파생본 400곳이 뒤처지면 그 자체가 결함이다.
  2. 매뉴얼은 ko·en 두 벌(AGENTS.md 구현 규약 5). 영문은 일관되므로 대개 손댈 것이 없지만, 장 제목이 바뀌면 카탈로그의 help.ch.* 도 함께 간다 — manual.spec.ts 가 본다.
  3. 스킬을 건드리면 버전을 올린다(AGENTS.md 구현 규약 6 · REQ-PLG-017). plugin.json 의 version, 카탈로그 둘, plugin/README.md, 매뉴얼 ko·en 이 한 묶음이다. 같은 버전이면 이미 설치한 쪽은 옛 사본을 계속 읽는다.
  4. SKILL.md 와 4.6 플러그인은 바이트 대조된다 — 한쪽만 고치면 plugin-package.spec.ts 가 막는다.
  5. 표제어를 더하거나 채택어를 바꾸면 이 문서의 버전과 README 의 문서 버전을 올린다(관리 규약 4).
