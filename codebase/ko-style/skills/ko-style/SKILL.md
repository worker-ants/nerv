# 한국어 문체 (ko-style)

한국의 개발자와 사용자가 실제로 쓰는 말로 쓴다. 이 스킬은 규칙과 예문, 스스로 검사하는 방법을 담는다. 플러그인 훅이 켜져 있으면 커밋 메시지 · PR 본문 · 문서 파일은 자동으로 검사된다.

## 먼저 지킬 것

1. 영어를 옮긴 듯한 표현을 쓰지 않는다. "권한을 필요로 한다"는 "권한이 필요하다"로, "값을 가지고 있다"는 "값이 있다"로, "반영되어진다"는 "반영된다"로 쓴다.
2. 사물을 주어로 사람의 동작을 쓰지 않는다. 화면 · 서버 · 문서 · 검사는 말하거나 묻거나 알지 않는다. "화면이 말한다"는 "화면에 표시된다"로 쓴다.
3. 한 문장에는 한 가지만 쓴다. 문장 끝에 줄표(—) 하나를 넣어 설명을 덧붙이지 않고 마침표로 끊는다. 제목 뒤의 부제와 "**이름** — 설명" 같은 이름표에는 줄표를 써도 된다.
4. 연결 어미 뒤에 쉼표를 찍지 않는다. "늘었지만, 아직"은 "늘었지만 아직"으로 쓴다.
5. "A가 아니라 B" 대비는 꼭 필요할 때 한 번만 쓴다.
6. 한 종류의 글 안에서는 말투를 섞지 않는다. 저장소 설정(`.ko-style.json`)이 글 종류마다 말투를 정한다.
7. 소리 내어 읽었을 때 한국어 화자가 그렇게 말하지 않을 문장이면 고친다.

## 고치지 않는 것

- 코드 · 식별자 · 파일 경로 · 명령 · URL · 숫자
- 인용한 글, 고유명사, 쓰지 않는 표현을 설명하는 예문
- 강도가 "참고"인 규칙("~에 대해", "~을 통해" 등)은 사람이 쓴 글에도 흔하다. 문맥을 보고 더 자연스러워질 때만 고친다.
- 뜻은 바꾸지 않는다. 고친 문장이 원래 문장과 같은 사실을 담고 있는지 확인한다.

## 팀 어휘와 글 종류별 말투

저장소 루트의 `.ko-style.json` 에 팀이 정한 어휘(`team`)와 글 종류별 말투(`surfaces`)가 있다. 지금 켜진 규칙 전체는 이 명령으로 본다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/ko-lint.mjs" rules
```

Claude Code 가 아닌 도구(Codex 등)에서는 이 SKILL.md 가 있는 폴더의 `scripts/ko-lint.mjs` 를 쓴다.

## 스스로 검사하기

```bash
node "${CLAUDE_SKILL_DIR}/scripts/ko-lint.mjs" check <파일>             # 파일 전체
node "${CLAUDE_SKILL_DIR}/scripts/ko-lint.mjs" check --staged            # 스테이징한 변경에서 새로 쓴 줄
node "${CLAUDE_SKILL_DIR}/scripts/ko-lint.mjs" check --base origin/main  # 이 브랜치에서 새로 쓴 줄
node "${CLAUDE_SKILL_DIR}/scripts/ko-lint.mjs" check --text "검사할 문장" --tone hapsyo
```

차단이 하나라도 있으면 종료 코드가 1이다. `--strict` 를 주면 경고도 실패로 센다.

## 훅이 하는 일

- 세션과 서브에이전트가 시작될 때 규칙 요약을 넣는다.
- 커밋 · PR 명령을 실행하기 전에 메시지를 검사하고, 걸리면 한 번 거부한다. 인용이나 고유명사처럼 그대로 둬야 하면 같은 메시지로 다시 실행한다. 두 번째는 통과한다.
- 문서 파일을 저장한 직후 새로 쓴 줄만 검사해서 걸린 표현을 알려 준다.
- 대화 답변이 끝나면 걸린 표현을 사용자에게 알리고, 다음 요청 때 모델에게도 알린다.
