Claude Code나 Codex를 NERV에 연결하는 절차입니다. 연결을 마치면 에이전트가 스펙을 읽고 작업을 클레임할 수 있습니다. 에이전트가 지금 하는 일은 세션 화면에 표시됩니다.

**전체 5단계**입니다. 중간에 막히면 마지막 절에서 원인을 찾아보세요. 무엇이 어떤 이유로 이렇게 맞물려 동작하는지는 [에이전트 연동](/help/agents) 장에서 설명합니다.

## 시작하기 전에

알아 둘 값이 세 가지 있습니다. **세 값 모두 이 화면에 이미 나와 있습니다.** 바로 위 카드의 값이 그것이고, 아래 명령과 파일도 모두 그 값으로 채워져 있습니다. 그대로 복사하시면 됩니다.

| 무엇           | 어디서 오나                      | 이 서버의 값  |
| -------------- | -------------------------------- | ------------- |
| NERV 서버 주소 | 관리자가 정한 `NERV_API_URL`     | `{{server}}`  |
| 프로젝트 slug  | 지금 보고 있는 프로젝트(왼쪽 열) | `{{project}}` |
| 내 역할        | 설정 → 멤버·역할                 | `{{role}}`    |

**브라우저 주소창의 주소와 다를 수 있습니다.** 화면과 API 를 서로 다른 호스트에 둔 환경에서는 주소창에 `app.…` 이 보이지만, 에이전트는 `api.…` 에 연결합니다. 위 표에 있는 값이 에이전트가 연결할 주소입니다.

역할이 중요한 이유는 **토큰의 권한이 역할보다 넓어질 수 없기** 때문입니다. `viewer` 역할로는 작업을 클레임하는 토큰을 만들 수 없습니다.

## 1. 토큰 발급

**설정 → 에이전트 토큰 → 새 토큰 발급**을 누릅니다. 이름은 어느 머신에서 쓰는 토큰인지 알 수 있게 짓습니다(`mac-02/claude-code`처럼).

- 토큰 값은 **발급 직후 한 번만** 표시됩니다. 창을 닫은 뒤에는 다시 볼 수 없어 새로 발급해야 합니다.
- **토큰은 프로젝트 하나에 묶입니다.** 발급 폼의 첫 칸에서 **프로젝트를 고릅니다**(기본값은 지금 보고 있는 프로젝트입니다). 토큰은 그 프로젝트에서만 쓸 수 있으므로, 프로젝트가 여럿이면 토큰도 프로젝트마다 따로 발급합니다. 어떤 권한 칸이 잠기는지도 **고른 프로젝트에 따라 정해집니다.** 역할은 프로젝트마다 다를 수 있기 때문입니다. 소속된 프로젝트가 없으면 발급 버튼을 누를 수 없고, 그 이유가 화면에 표시됩니다.
- **만료 기간을 고를 수 있습니다**: 30일 · 90일 · 1년 · 만료 없음. 기본값은 만료 없음입니다. 만료된 토큰은 그 순간부터 거절되므로 폐기한 것과 같습니다. 만료일은 목록에서 확인할 수 있습니다.
- 발급하면 카드가 나타나고, **이 토큰의 정보**(프로젝트·권한·만료)와 **연결 3단계**가 차례로 표시됩니다: ① 토큰(복사 버튼) ② 플러그인 설치 명령 두 줄(Claude Code 에서 실행) ③ 작업 저장소에서 실행할 `nerv-init` 명령 한 줄. ③ 은 설치 캐시에서 `nerv-init` 을 찾아 실행하는 형태라 그대로 붙여 넣으면 됩니다. 이 명령이 아래 2·3단계의 파일을 한 번에 만듭니다. **이 명령은 토큰을 셸 기록에 남깁니다.** 남기지 않으려면 `--token` 과 그 값을 빼고 실행하세요. 그러면 토큰을 입력하라는 프롬프트가 나오고, 입력하는 값은 화면에 보이지 않습니다. 토큰이 **처음 쓰이면** 카드의 표시가 **"연결됨 · 머신 이름"** 으로 바뀝니다.
- 발급한 토큰 목록의 **첫 열은 프로젝트**입니다. 폐기·만료된 토큰은 접혀 있고, [폐기·만료된 것도 보기]를 누르면 펼쳐집니다. **조직 admin**(조직 전체 역할이 admin 인 사람)은 설정의 조직 항목에 있는 **[조직 전체 토큰]** 화면에서 누가 어느 프로젝트에 어떤 토큰을 가지고 있는지 볼 수 있습니다. 그 화면의 **[폐기]로 다른 사람의 토큰을 끊는 것도 조직 admin 만** 할 수 있습니다. 프로젝트의 admin 은 자기 토큰만 폐기할 수 있습니다. 폐기는 되돌릴 수 없어서 한 번 더 확인합니다.
- 권한은 처음에 **[권장]** 으로 선택되어 있습니다. 에이전트가 스킬 다섯(next·spec·impl·question·review)을 쓰는 데 필요한 `spec:read` · `spec:draft` · `task:claim` · `task:update` · `review:submit` · `agent-session:launch` 입니다. 이 중 내 역할에 없는 권한은 빼고 발급됩니다(잠긴 권한이 모르는 사이에 포함되지는 않습니다). 권한을 다르게 주려면 **[직접 고르기]** 로 바꾼 뒤 칸을 켜고 끕니다. 권한 이름 아래에는 **그 권한으로 무엇을 할 수 있는지** 한 줄 설명이 있습니다.
- **`agent-session:launch` 는 빼지 마세요.** `nerv_bootstrap` 에 이 권한이 필요해서, 빠지면 아래 4·5단계를 처음부터 진행할 수 없습니다. [직접 고르기]로 권한을 줄일 때 가장 흔히 하는 실수입니다.
- **토큰의 권한은 역할을 넘지 않습니다.** 내 역할에 없는 권한은 **흐리게 잠긴 채로** 표시됩니다. 예를 들어 `review:resolve` 는 admin · planner · qa 역할에만 있어서 `developer` 에게는 잠겨 있습니다. 목록에서 숨기지 않는 이유는 사람 전용 권한과 같습니다. 왜 줄 수 없는지를 화면에서 바로 알 수 있어야 하기 때문입니다.
- 나중에 역할이 넓어지면 **이미 발급한 토큰에도 그 즉시 반영됩니다.** 다시 발급할 필요가 없습니다.
- `spec:approve`와 `approval:decide`는 체크박스 자체가 잠겨 있습니다. 승인은 사람이 하는 일이라 토큰에 줄 수 없습니다.

## 2. 환경변수

**이 단계는 설정 파일을 직접 만드는 방법입니다.** 플러그인을 먼저 설치했다면(3-A), 3-A 끝에 나오는 명령 한 줄이 이 단계의 파일과 다음 단계의 `.mcp.json` 을 **대신 만들어 줍니다.** 이미 있는 값은 덮어쓰지 않습니다. 어떤 파일이 만들어지는지 알고 싶거나 직접 만들고 싶을 때 이 단계를 따르세요.

**이 값은 머신이 아니라 프로젝트에 따라 달라집니다.** 셸 프로필에 `export` 로 적어 두면 그 머신에서는 한 프로젝트만 쓸 수 있습니다. 다른 프로젝트로 바꿀 때마다 프로필을 고치고 세션을 다시 시작해야 합니다. 그래서 값을 **작업 저장소 안에** 둡니다.

### 기본 — 저장소의 `.claude/settings.local.json`

```jsonc
{
  "env": {
    "NERV_SERVER": "{{server}}",
    "NERV_PROJECT": "{{project}}",
    "NERV_TOKEN": "<1단계에서 받은 토큰>",
  },
}
```

이 파일은 **기본으로 git 추적에서 제외되므로** 토큰이 커밋되지 않습니다. 저장소마다 다른 값을 쓸 수 있고, 셸 프로필을 고칠 필요도 없습니다.

### `.nerv/env` — Codex 를 위한 자리입니다 (지금은 쓰지 않습니다)

**Claude Code 만 쓴다면 위 파일 하나로 충분합니다.** 값을 두 곳에 두지 마세요. 두 곳의 값이 서로 다르면 어느 쪽 값이 적용될지가 상황마다 달라집니다.

`.nerv/env` 는 Claude Code 가 아닌 환경(Codex)을 위한 폴백입니다. 플러그인의 스크립트가 이 파일을 읽습니다.

```bash
NERV_SERVER={{server}}
NERV_PROJECT={{project}}
NERV_TOKEN=<1단계에서 받은 토큰>
```

**이미 설정된 값은 덮어쓰지 않습니다.** 회사에서 관리하는 기기의 설정이나 셸에 있는 값이 항상 우선합니다. 그리고 `NERV_` 로 시작하는 변수만 읽습니다.

> 이 파일로는 Codex 를 **절반만** 지원합니다. 알림·훅은 플러그인 스크립트가 이 파일을 직접 읽어 동작합니다. 하지만 Codex 의 MCP 인증은 환경변수 이름만 받기 때문에 이 파일의 값이 적용되지 않습니다. Codex 지원은 아직 준비 중입니다.

### 그 머신에서 한 프로젝트만 쓴다면

예전처럼 셸 프로필에 두어도 됩니다. 다만 `.claude/settings.local.json` 에 같은 값이 있으면 그 값이 적용됩니다. `.nerv/env` 는 이미 있는 값을 덮어쓰지 않으므로, 셸 프로필의 값이 `.nerv/env` 보다 우선합니다.

```bash
export NERV_TOKEN="<1단계에서 받은 토큰>"
export NERV_PROJECT="{{project}}"
```

`NERV_HOSTNAME`은 세션 화면에서 "누구의 어떤 머신인지"를 보여 주는 값입니다. **설정해 두는 것이 좋습니다.** 일부 훅은 서버로 바로 보내는 이벤트에 이 변수 값을 그대로 담습니다. 그래서 이 값이 비어 있으면 머신 이름이 없는 세션이 목록에 남습니다. 두 대 이상에서 에이전트를 돌리기 시작하면 어느 세션이 어느 머신의 것인지 구분할 수 없습니다.

```bash
export NERV_HOSTNAME="$(hostname -s)"
```

이 값은 **표시용**입니다. 헤더 값은 보내는 쪽에서 얼마든지 바꿀 수 있으므로 권한 판정에는 쓰지 않습니다.

**토큰을 저장소에 커밋하지 마세요.** 작업 저장소의 `.gitignore`에 `.nerv/`도 추가합니다. 환경 파일과 플러그인의 캐시·오프라인 큐가 이 폴더에 쌓입니다.

## 3-A. Claude Code에 플러그인 설치

Claude Code 안에서 아래 두 줄을 실행합니다. **이 서버가 배포하는 플러그인을 받습니다.**

```text
/plugin marketplace add {{server}}/plugin/marketplace.json
/plugin install nerv@nerv
```

그다음 Claude Code 를 **재시작**합니다. `/plugin` 목록에 `nerv` v{{version}}이 활성 상태로 보이면 됩니다.

이 서버에서 받는 이유는 **버전이 이 서버와 맞기** 때문입니다. 카탈로그를 이 서버가 직접 만들기 때문에, 언제나 이 서버에 맞는 버전을 받습니다. 외부로 나갈 수 없는 망에서는 이 방법밖에 없기도 합니다.

> **이 주소로 설치가 안 되면 GitHub 에서 받습니다.** 첫 줄만 `add worker-ants/nerv` 로 바꾸면 됩니다. 설치 명령은 그대로이고 **받는 파일도 같습니다**(같은 마켓플레이스를 받는 두 경로이므로 둘을 동시에 등록하지는 않습니다).
>
> 서버에서 받으려면 **https · 공개 주소 · 신뢰된 CA** 세 가지를 모두 갖춰야 합니다. `Archive URLs must use https://…` 로 거부되면 앞의 두 가지 문제이고(이 둘은 위 카드가 미리 알려 줍니다), 인증서 오류로 끝나면 세 번째 문제입니다. **사내 CA 로 발급한 인증서의 문제는 브라우저에서 확인할 수 없어서 카드에도 나타나지 않습니다.**

사내 git 마켓플레이스를 쓰는 환경이라면 그 git URL 을 대신 넣습니다(`/plugin install nerv@nerv-internal`).

**미리 설치해 둘 도구가 두 가지 있습니다.** 훅 포워더는 `curl` 을, statusline 과 아웃박스는 `jq` 를 씁니다. 이 도구가 없으면 오류 없이 **조용히 아무 일도 하지 않습니다.**

> 새 버전을 받으려면 `/plugin marketplace update` 를 실행합니다. 관리자가 플러그인 버전을 올렸을 때만 새 버전을 받습니다. 버전이 같으면 이미 받아 둔 사본을 그대로 씁니다.

설치되는 것은 네 가지입니다.

| 무엇                            | 하는 일                                                                |
| ------------------------------- | ---------------------------------------------------------------------- |
| 스킬 5종                        | `/nerv:next` `/nerv:spec` `/nerv:impl` `/nerv:question` `/nerv:review` |
| 훅                              | 에이전트가 하는 일을 세션 화면으로 보냅니다                            |
| statusline                      | 지금 맡은 클레임·남은 시간·범위 겹침을 프롬프트 줄에 표시합니다        |
| 서브에이전트 `nerv-spec-writer` | 스펙 초안 작성만 맡는 전용 에이전트                                    |

**`nerv_*` 도구는 이 네 가지에 들어 있지 않습니다.** 저장소에 `.mcp.json` 이 있어야 쓸 수 있습니다. 서버 주소와 토큰이 프로젝트마다 다르기 때문에 플러그인에 이 파일을 넣지 않았습니다.

**대신 이 파일을 만들어 주는 명령이 들어 있습니다.** 작업 저장소에서 한 번 실행하면 `.mcp.json` · `.claude/settings.local.json` 의 환경변수 · `.gitignore` 의 `.nerv/` 가 한꺼번에 준비됩니다. **주소와 프로젝트는 이 서버의 값으로 채워 두었으니** 입력할 것은 토큰뿐입니다. 토큰은 화면에 보이지 않게 입력받습니다.

```bash
cd <작업 저장소>
"$(ls -d "$HOME"/.claude/plugins/cache/*/nerv/*/bin/nerv-init | sort -V | tail -1)" \
  --server {{server}} --project {{project}}
```

**이미 있는 값은 덮어쓰지 않습니다.** 토큰이 이미 적혀 있으면 그대로 두고, 그렇다고 알려 줍니다. 토큰을 바꾸려면 그 파일을 직접 고치세요. `.mcp.json` 이 이미 있는데 `nerv` 항목만 없으면, 파일은 건드리지 않고 **추가할 항목을 출력해 줍니다.**

설정이 덜 된 저장소에서는 세션을 시작할 때 무엇이 빠졌는지 알려 줍니다. **알려 주기만 하고 파일을 만들지는 않습니다.** 설정은 사람이 직접 시작합니다. NERV 를 쓰는 흔적이 없는 저장소에서는 아무것도 표시하지 않습니다.

파일을 만든 다음에는 **Claude Code 를 다시 시작합니다.** 새로 생긴 `.mcp.json` 은 다시 시작할 때 읽힙니다.

직접 만들려면 아래 내용을 넣습니다(2단계의 환경변수와 함께 씁니다).

```json
{
  "mcpServers": {
    "nerv": {
      "type": "http",
      "url": "${NERV_SERVER:-{{server}}}/mcp",
      "headers": {
        "Authorization": "Bearer ${NERV_TOKEN}",
        "X-NERV-Project": "${NERV_PROJECT}"
      }
    }
  }
}
```

`/mcp` 에 `nerv` 가 connected 로 보이면 됩니다.

**회사에서 관리하는 기기라면 이 단계를 건너뜁니다.** 관리형 설정에 마켓플레이스 등록과 플러그인 활성화가 이미 되어 있고, `NERV_SERVER`·`NERV_PROJECT`도 관리형 설정에서 가져옵니다. 이 경우에는 1·2·4·5단계만 하면 됩니다.

## 3-B. Codex에 연결

Codex에는 플러그인 형식이 없습니다. 대신 Codex 를 쓰는 저장소에 **파일 두 개를 둡니다.** 두 파일의 초안은 플러그인 패키지의 `codex/`에 담겨 함께 배포됩니다.

```bash
mkdir -p <내 저장소>/.codex
cp <플러그인>/codex/config.toml <내 저장소>/.codex/config.toml
cp <플러그인>/codex/AGENTS.md   <내 저장소>/AGENTS.md
```

`AGENTS.md`가 이미 있으면 덮어쓰지 말고 **"단일 진실"·"세션 시작 시 반드시" 두 절만** 복사해 넣습니다.

복사한 `.codex/config.toml`에서 세 곳을 내 값으로 바꿉니다: `url` · `X-NERV-Project` · (쓴다면) `[otel] environment`.

```toml
[mcp_servers.nerv]
url = "{{server}}/mcp"
bearer_token_env_var = "NERV_TOKEN"
http_headers = { "X-NERV-Project" = "{{project}}" }
startup_timeout_sec = 20

# 사람 승인 레인 — A3 도구는 승인 없이 실행되지 않습니다
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

**`config.toml` 에는 토큰을 적지 않습니다.** `bearer_token_env_var`에 적힌 대로 `NERV_TOKEN` 환경변수에서 토큰을 읽습니다. 이 값은 2단계에서 정한 위치(`.nerv/env` 또는 셸)에서 가져옵니다. Codex 는 `.claude/settings.local.json` 을 읽지 않으므로, Codex 를 쓴다면 `.nerv/env` 에 둡니다.

Claude Code는 아직 `AGENTS.md`를 자동으로 읽지 않습니다. 같은 저장소에서 두 에이전트를 모두 쓴다면 `CLAUDE.md`에 아래 한 줄을 넣습니다.

```markdown
@AGENTS.md
```

**Codex에서 되는 것과 안 되는 것.**

- 도구는 **모두 쓸 수 있습니다.** `bootstrap → next → claim → heartbeat → release`를 도구만으로 끝까지 진행할 수 있습니다. 핵심 기능은 모두 도구로 제공되기 때문입니다.
- 스킬 파일(`SKILL.md`)은 그대로 재사용합니다. 개방형 형식이라 Codex 에서도 같은 파일을 씁니다.
- **훅 텔레메트리는 없습니다.** 그래서 세션 화면에서 Codex 세션은 덜 자세하게 보입니다. 모든 행동이 표시되지는 않고, 에이전트가 직접 올리는 마일스톤만 표시됩니다.
- 저장소의 `.codex/config.toml`은 **신뢰한 프로젝트에서만** 읽힙니다. 처음 열 때 한 번 승인해야 합니다.

## 4. 연결 확인

- **Claude Code**: 프로젝트 저장소에서 Claude Code 를 실행한 뒤 `/mcp` 를 입력합니다. `nerv` 서버가 connected이고 `nerv_*` 도구 목록이 보이면 됩니다.
- **Codex**: 세션을 시작하고 `nerv_bootstrap`을 호출합니다. 응답에 `session_id`와 게이트 정책이 담겨 옵니다.

어느 쪽이든 **웹의 세션 화면에 내 세션 카드가 나타나야** 제대로 연결된 것입니다.

Claude Code 라면 세션 카드는 `nerv_bootstrap` 을 호출하기 **전에** 나타납니다. 세션 시작 훅이 세션을 직접 등록하기 때문입니다. 그러니 도구 목록은 보이는데 카드가 나타나지 않는다면 **훅 쪽**을 확인하세요. 토큰이 비었거나, `curl` 이 없거나, 서버에 연결하지 못한 경우입니다. 포워더는 실패해도 오류를 내지 않으므로 화면에는 아무것도 표시되지 않습니다.

## 5. 첫 작업

```text
/nerv:next
```

스킬이 `nerv_bootstrap`부터 호출하고, 다음 작업을 추천한 뒤 클레임까지 진행합니다. Codex라면 같은 순서대로 도구를 직접 호출합니다. 그 순서는 복사해 둔 `AGENTS.md`에 적혀 있습니다.

## 잘 안 될 때

| 증상                               | 대개는 이것                                                                                                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/mcp`에 `nerv`가 없다             | 설치 후 재시작하지 않았거나 저장소에 `.mcp.json` 이 없습니다. 3-A 의 명령을 한 번 실행하세요                                                                     |
| 서버에 연결되지 않는다             | `url` 오타이거나 사내망 밖에 있습니다. 이 장 상단의 카드에 적힌 주소와 비교해 보세요                                                                             |
| `NERV_UNAUTHENTICATED`             | `NERV_TOKEN`이 비었거나 폐기됐습니다. 설정 → 에이전트 토큰에서 다시 발급하세요                                                                                   |
| `NERV_FORBIDDEN` · 권한 부족       | 토큰에 필요한 권한이 없거나, 발급 시점의 역할로는 그 일을 할 수 없습니다                                                                                         |
| 도구는 되는데 프로젝트가 안 보인다 | **그 토큰이 다른 프로젝트에서 발급됐습니다.** 토큰의 프로젝트는 발급할 때 정해지고 헤더로 바꿀 수 없습니다. 그 프로젝트에서 토큰을 새로 발급하세요               |
| `project_mismatch`                 | `X-NERV-Project` 와 토큰의 프로젝트가 다릅니다. 오류 메시지에 두 값이 모두 나오니 맞는 쪽으로 고치세요                                                           |
| 세션 카드가 나타나지 않는다        | 훅이 서버에 연결하지 못했습니다. `NERV_TOKEN`·`NERV_SERVER` 와 `curl` 을 확인하세요. 훅은 실패해도 오류를 표시하지 않습니다                                      |
| 검토 요청이 그냥 실패한다          | A3 도구라서 사람이 웹에서 직접 눌러야 합니다([받은 요청](/help/inbox))                                                                                           |
| `NERV_RATE_LIMIT`                  | 요청이 너무 잦습니다. 한도는 토큰 하나당 분당 300건, 훅은 세션당 120건입니다. 응답의 `retry_after_s`만큼 기다리세요. 병렬로 재시도해서 한도를 피하려 하지 마세요 |
| 세션이 `stale`로 바뀐다            | 하트비트가 끊겼습니다. 30분이 지나면 클레임이 회수됩니다([세션](/help/sessions))                                                                                 |
