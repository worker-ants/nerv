## ⌘K — 어디로든 가기

`⌘K`(윈도·리눅스는 `Ctrl+K`)로 빠른 이동 창을 엽니다. 목록은 무리로 나뉩니다.

| 무리                | 무엇이 있나                                                    |
| ------------------- | -------------------------------------------------------------- |
| **고정** · **최근** | 고정한 문서와 최근에 연 스펙·작업 — 입력이 비어 있을 때만      |
| **이 프로젝트**     | 개요 · 스펙 · 작업 · 세션 · 리뷰 — 프로젝트 안에 있을 때       |
| **이동**            | 홈 · 받은 요청 · 알림 · 설정의 네 탭 · 도움말 · 이 화면 도움말 |
| **프로젝트**        | 지금 조직의 프로젝트                                           |
| **문서**            | 치는 말에 맞는 스펙·요구사항·작업 — 프로젝트 안에서만 찾습니다 |

치면 무리마다 이름으로 거릅니다 — "토큰" 을 치면 설정의 토큰 탭이, 프로젝트 이름을 치면 그 프로젝트가 나옵니다. 영어 낱말(`inbox` · `settings` · `tokens`)로도 맞습니다. **고정 ID를 그대로 붙여넣으면** 그 문서·요구사항·작업으로 곧장 갑니다(작업은 키로만 찾습니다). 요구사항을 고르면 그 스펙의 요구사항 탭이, 헤딩에 맞은 줄을 고르면 그 절이 열립니다.

**문서 검색은 프로젝트 안의 일입니다.** 홈·받은 요청·알림·설정에서도 창은 화면과 프로젝트로 데려가지만, 스펙·작업은 찾지 않습니다 — 자리표시자가 그렇게 말합니다.

| 키              | 동작      |
| --------------- | --------- |
| `⌘K` · `Ctrl+K` | 열기·닫기 |
| `↑` · `↓`       | 결과 이동 |
| `Enter`         | 열기      |
| `Esc`           | 닫기      |

입력이 비어 있으면 **고정한 것과 최근에 연 것**이 위에 놓입니다 — 고정한 것이 먼저입니다. **최근은 실제로 연 문서입니다** — 트리·링크·알림으로 연 스펙과 작업도 쌓입니다. 줄마다 어느 프로젝트의 것인지 적혀 있고, 누르면 **그 프로젝트의** 문서로 갑니다(다른 프로젝트에 있어도, 홈에 있어도). 지금 조직의 것만 보입니다.

줄 오른쪽의 **☆** 를 누르면 그 문서가 고정되고(★), 다시 누르면 풀립니다. 최근 목록은 어제 본 것이 오늘 밀려나지만 **매일 여는 대여섯은 그러면 안 되기** 때문입니다. 고정은 테마·언어와 같이 **이 브라우저에** 남습니다.

창 안에서 `Tab` 은 입력칸과 ☆ 단추 사이를 돌고 뒤의 화면으로 나가지 않습니다. `Esc` 는 어디에 있든 닫고, 닫으면 **열기 전에 있던 자리**로 돌아갑니다. 화면 읽기 도구에는 입력칸이 목록을 거느린 콤보 상자로, 지금 고른 줄이 그 줄로 읽힙니다.

## 화면을 키보드로

**첫 `Tab` 에 "본문으로 건너뛰기" 가 보입니다** — `Enter` 를 누르면 헤더와 사이드바를 건너 본문에서 시작합니다.

**메뉴**(왼쪽 열의 조직 · 헤더의 도움말 · 사용자)는 열면 첫 항목으로 갑니다. `Esc` 로 닫으면 연 단추로 돌아오고, 메뉴 밖으로 `Tab` 하면 저절로 닫힙니다.

**스펙 트리는 `Tab` 한 칸입니다** — 트리로 들어간 뒤에는 키로 움직입니다. 펼침 단추는 `Tab` 을 받지 않습니다.

| 키             | 동작                                       |
| -------------- | ------------------------------------------ |
| `↑` · `↓`      | 줄 이동                                    |
| `→`            | 접힌 가지를 편다 — 펴져 있으면 첫 자식으로 |
| `←`            | 편 가지를 접는다 — 잎이면 부모로           |
| `Home` · `End` | 처음 · 끝                                  |
| `Enter`        | 그 문서를 연다                             |

**알림은 줄을 `Tab` 으로 골라 `Enter` 로 엽니다** — 누른 것과 같이 읽음으로 하고 그 자리로 갑니다. 줄에 포커스가 있거나 터치 화면이면 **[읽음]** 이 늘 보입니다.

## 다이얼로그와 패널

`Esc` 로 닫는 자리 — **스펙 메타** 다이얼로그([⋯ 메타]), **기준선 생성** 다이얼로그, 다이어그램의 **전체 화면**, **관계 그래프**에서 고른 노드의 패널, 좁은 화면에서 띠로 연 **스펙 트리**(닫으면 띠의 단추로 돌아갑니다), 그리고 **한 번 더 묻는 확인**(취소와 같습니다). 확인이 떠 있는 다이얼로그에서는 `Esc` 가 확인만 닫습니다. 다이얼로그가 열려 있는 동안 `Tab` 은 그 안을 돌고, 닫으면 **연 단추로** 돌아갑니다.

리뷰의 발견을 처리할 때 스펙을 고르는 칸에서는 `↓` 로 결과 목록으로 내려가고 `Enter` 로 첫 결과를 바로 고릅니다.

## 받은 요청

| 키        | 동작             |
| --------- | ---------------- |
| `j` · `k` | 카드 사이 이동   |
| `a`       | 승인             |
| `r`       | 거절             |
| `c`       | 코멘트 쓰기      |
| `x`       | 일괄에 넣기·빼기 |
| `⇧X`      | 보이는 것 전체   |
| `⇧A`      | 일괄 승인        |
| `⇧R`      | 일괄 거절        |
| `Esc`     | 선택 해제        |

입력창에 커서가 있을 때는 동작하지 않습니다. 일괄 키가 **대문자**인 것은 단건 키와 겹치지 않게 하기 위해서입니다 — 한 건과 스무 건을 가르는 차이는 `Shift` 만큼은 되어야 합니다. 확인 목록이 떠 있는 동안에는 `a`·`r`·`c` 가 듣지 않습니다.

**질문 카드에서는 `a` 와 `r` 이 듣지 않습니다.** 질문은 승인하거나 거절하는 것이 아니라 답하는 것이라서, 답을 쓰는 `c` 만 열립니다.

**내가 올린 결재에서는 `a` 가 열리지 않습니다** — 자기 것을 자기가 승인하지 못하게 하는 규칙이고 — **내가 쓴 초안·내 세션이 쓴 초안도 같습니다**, admin 이거나 멤버가 2명 미만인 프로젝트에서는 예외입니다([받은 요청](/help/inbox)).

그 밖의 경우, 결재 권한이 없는 역할이 `a` 를 눌러도 조용히 넘어가지 않고 **서버가 거절합니다.** **처리됨 탭의 카드에서는 단추도 키도 듣지 않습니다** — 이미 결정된 카드는 `a`·`r`·`c` 를 무시합니다(누를 수 있는 것이 할 수 있다는 뜻이어야 합니다).

## 작업 상세(보드 위 시트)

| 키        | 동작                        |
| --------- | --------------------------- |
| `j` · `k` | 같은 레인의 다음·앞 작업    |
| `Esc`     | 닫기 — 보드의 필터는 그대로 |

입력창에 커서가 있을 때는 동작하지 않습니다([작업](/help/tasks)).

## 언어

사용자 메뉴(헤더 오른쪽 이름 ▾)에서 **한국어 / English**를 고릅니다. 화면과 서버가 돌려주는 에러 메시지가 함께 바뀝니다. **로그인·가입·초대 화면**에는 사용자 메뉴가 없어서, 화면 아래에 같은 단추가 있습니다 — 로그인하기 전에도 바꿀 수 있습니다.

**CLI 는 따로입니다.** 문구 한 벌을 같이 쓰기는 하지만, CLI 의 언어는 웹에서 고른 값이 아니라 환경변수(`NERV_LANG`, 없으면 `LC_ALL`·`LANG`)를 봅니다.

번역하지 않는 것이 셋 있습니다: **식별자**(`ready` · `approved` 같은 상태값)와 **운영자용 로그**, 그리고 **문서에 저장된 내용**입니다. 상태값이 언어마다 다르면 화면과 로그가 서로 다른 말을 하게 됩니다.

## 화면 색

같은 메뉴의 언어 바로 아래에서 **밝게 / 어둡게 / 시스템**을 고릅니다. `시스템`은 "고르지 않겠다"는 선택이라, 그동안은 브라우저(또는 운영체제)의 설정을 따라갑니다 — 기계가 밤에 어두워지면 화면도 함께 어두워집니다. 밝게나 어둡게를 고르면 그 선택이 기계 설정을 이깁니다.

**테마는 계정이 아니라 이 브라우저에 남습니다.** 같은 사람이 낮의 노트북과 밤의 데스크톱을 다르게 쓰기 때문입니다 — 다른 기계에서는 거기서 다시 고릅니다.

**언어도 같은 자리에 남습니다.** 계정을 따라다니지 않으므로, 다른 기계에서 처음 열면 브라우저 언어로 시작합니다 — 거기서 다시 고르면 됩니다.
