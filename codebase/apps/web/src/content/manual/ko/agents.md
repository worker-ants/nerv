NERV에 에이전트를 연결하면 Claude Code나 Codex가 스펙을 읽고, 작업을 클레임하고, 하고 있는 일을 실시간으로 보고합니다. 연결되는 구성 요소는 다섯 가지입니다: **MCP 도구 · 훅 · 스킬 · statusline · 서브에이전트**.

이 장에서는 각 구성 요소가 **어떻게 맞물려 동작하는지** 설명합니다. 실제 연결 절차는 [플러그인 설치](/help/install) 장을 보세요.

## 무엇이 붙는가

- **MCP 도구** — 에이전트는 이 도구로 NERV를 읽고 씁니다. 서버 이름은 `nerv`이고, 도구 이름은 `nerv_*` 형식입니다.
- **훅** — 에이전트가 하는 일을 세션 화면으로 전달합니다. 훅이 없는 환경에서는 에이전트가 직접 이벤트를 보냅니다.
- **스킬** — `/nerv:next` 처럼 사람이 호출하는 절차입니다. 무엇을 어떤 순서로 할지가 담겨 있습니다.
- **statusline** — 현재 클레임과 남은 시간, 범위 겹침을 프롬프트 줄에 표시합니다.
- **서브에이전트** — `nerv-spec-writer`입니다. 스펙 초안 작성만 맡는 전용 에이전트입니다.

권한을 정하는 것은 스킬이 아니라 **토큰입니다.** 스킬은 절차를 편하고 자세하게 안내할 뿐이며, 서버 게이트를 우회할 수 없습니다.

## 토큰과 권한

에이전트가 할 수 있는 일은 **토큰에 따라 정해집니다**(발급 방법은 [플러그인 설치](/help/install) 장의 1단계).

- 토큰 값은 **발급 직후 한 번만** 보입니다. 그 자리에서 복사해 두세요.
- 설정 → 에이전트 토큰의 **내 토큰** 목록에는 **모든 조직**의 토큰이 함께 표시됩니다. 조직이 둘 이상이면 프로젝트 칸이 "조직 / 프로젝트" 형식으로 표시되어 어느 조직의 토큰인지 알 수 있습니다.
- 권한은 `resource:action` 형식으로 표기하며 **10종**입니다: `spec:read` · `spec:draft` · `spec:meta` · `spec:evidence` · `task:claim` · `task:update` · `review:submit` · `review:resolve` · `agent-session:launch` · `import:write`.
- **`spec:evidence` 는 CI 용 권한입니다.** 요구사항에 PR·테스트 증적을 붙이는 일만 할 수 있고, 초안이나 작업은 건드리지 못합니다. 빌드 파이프라인에 주는 토큰은 이 권한 하나만 켜면 됩니다.
- **프로젝트 설정 변경·보관·복구는 토큰으로 할 수 없습니다.** 역할이 admin 이어도 마찬가지입니다. 게이트 정책을 낮추는 일은 게이트를 면제하는 일만큼 무겁기 때문에 사람이 웹에서 직접 합니다.
- **`spec:approve`와 `approval:decide`는 토큰에 부여할 수 없습니다.** 발급 화면에서 두 권한은 **보이지만 잠겨** 있습니다. 목록에서 아예 빼 버리면 "왜 승인 권한은 토큰에 못 주지?" 라는 물음의 답을 화면에서 찾을 수 없기 때문입니다. 보이지만 고를 수 없게 두면 이 규칙을 화면에서 바로 알 수 있습니다. 승인은 사람이 하는 일입니다.
- **질문 답변·게이트 면제·받은 요청 읽기도 토큰으로 할 수 없습니다.** admin 역할도 예외가 아닙니다. 에이전트가 자기 질문에 스스로 답하면 사람이 지키는 게이트가 없는 것과 같기 때문입니다. 답변은 사람이 웹의 받은 요청 화면에서 합니다.
- 토큰의 권한은 역할보다 넓어질 수 없습니다. 발급할 때의 역할이 상한입니다.
- 목록에는 마지막 사용 시각과 마지막 호스트가 기록됩니다. 모르는 호스트가 보이면 바로 그 토큰을 폐기하세요.

## 스킬

| 스킬             | 하는 일                   |
| ---------------- | ------------------------- |
| `/nerv:next`     | 다음 작업 추천과 클레임   |
| `/nerv:spec`     | 스펙 초안·변경 요청 작성  |
| `/nerv:impl`     | 클레임한 작업의 구현 절차 |
| `/nerv:question` | 질문 올리기와 답 기다리기 |
| `/nerv:review`   | 리뷰 제출과 발견 처분     |

## 도구 티어

도구마다 위험 티어가 정해져 있습니다.

- **A1** — 읽기입니다. 승인 없이 호출합니다.
- **A2** — 쓰기입니다. 되돌릴 수 있는 변경만 여기에 속합니다.
- **A3** — **사람 승인이 필요합니다.** 검토 요청(`nerv_spec_submit_review`)과 `critical` 하향이 여기에 속합니다. A3 도구는 어떤 스킬의 무승인 허용 목록에도 들어가지 않습니다. **결정은 요청한 세션에 다음 하트비트 때 전달됩니다.** 승인·거절·코멘트 모두 마찬가지여서, 그 세션은 이어서 무엇을 할지 알 수 있습니다.

## 문서 가져오기

기존 저장소의 문서를 스펙과 작업으로 가져올 때는 CLI를 씁니다.

```
nerv import <spec|plan|review|docs|rebuild-map> --root <경로> --project <slug> [--apply]
```

모드는 다섯 가지입니다. `spec`·`plan`·`review`·`docs` 넷은 문서를 가져오고, `rebuild-map` 은 이미 가져온 항목의 대응표를 다시 만듭니다.

**프로파일은 반드시 지정하세요.** `--profile` 과 `--profile-file` 을 모두 생략하면 CLI 가 알리지 않고 기본 프로파일을 씁니다. 다른 저장소의 규칙으로 내 문서를 읽는 셈이어서, 결과가 어긋나도 알아채기 어렵습니다.

`--apply` 를 붙이려면 서버와 토큰을 지정해야 합니다(`--server`·`--token` 또는 `NERV_SERVER`·`NERV_TOKEN`). 없으면 명령이 거부됩니다.

`--apply` 없이 실행하면 **dry-run**입니다. 아무것도 쓰지 않고 리포트만 출력합니다. 리포트에는 읽은 건수와 변환한 건수, 그리고 **무엇을 왜 건너뛰었는지**가 줄 단위로 적힙니다. 사람이 그 리포트를 확인하고 판단한 뒤에 `--apply` 를 붙여 실행합니다.

같은 명령을 다시 실행해도 안전합니다. 이미 가져온 항목은 다시 만들지 않고, 비어 있던 링크만 채웁니다.
