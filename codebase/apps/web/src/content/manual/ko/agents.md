NERV에 에이전트를 연결하면 Claude Code나 Codex가 스펙을 읽고 작업을 클레임합니다. 하고 있는 일도 실시간으로 보고합니다. 연결되는 구성 요소는 **MCP 도구, 훅, 스킬, statusline, 서브에이전트** 다섯 가지입니다.

이 장에서는 각 구성 요소가 **어떻게 맞물려 동작하는지** 설명합니다. 실제 연결 절차는 [플러그인 설치](/help/install) 장을 보세요.

## 연결되는 구성 요소 {#components}

- **MCP 도구** — 에이전트는 이 도구로 NERV의 데이터를 읽고 씁니다. 서버 이름은 `nerv`이고 도구 이름은 `nerv_*` 형식입니다.
- **훅** — 에이전트가 하는 일을 세션 화면으로 전달합니다. 훅이 없는 환경에서는 에이전트가 직접 이벤트를 보냅니다.
- **스킬** — `/nerv:next`처럼 사람이 호출하는 절차입니다. 무엇을 어떤 순서로 할지가 담겨 있습니다.
- **statusline** — 현재 클레임과 남은 시간, 범위 겹침을 프롬프트 줄에 표시합니다.
- **서브에이전트** — `nerv-spec-writer`입니다. 스펙 초안 작성만 맡는 전용 에이전트입니다.

권한은 스킬이 아니라 **토큰에 달려 있습니다.** 스킬은 절차를 편하고 자세하게 안내할 뿐입니다. 서버 게이트를 우회할 수는 없습니다.

## 토큰과 권한 {#tokens}

에이전트가 할 수 있는 일은 **토큰에 따라 정해집니다**(발급 방법은 [플러그인 설치 장의 1단계](/help/install#token)).

- 토큰 값은 **발급 직후 한 번만** 보입니다. 그 자리에서 복사해 두세요.
- 설정 → 에이전트 토큰의 **내 토큰** 목록에는 **모든 조직**의 토큰이 함께 표시됩니다. 조직이 둘 이상이면 프로젝트 칸이 "조직 / 프로젝트" 형식으로 표시되어 어느 조직의 토큰인지 알 수 있습니다.
- 권한은 `resource:action` 형식으로 표기하며 모두 **10종**입니다. `spec:read`, `spec:draft`, `spec:meta`, `spec:evidence`, `task:claim`, `task:update`, `review:submit`, `review:resolve`, `agent-session:launch`, `import:write`가 있습니다.
- **`spec:evidence`는 CI 용 권한입니다.** 이 권한으로는 요구사항에 PR과 테스트 증적을 붙이는 일만 할 수 있습니다. 초안이나 작업은 건드리지 못합니다. 빌드 파이프라인에 주는 토큰은 이 권한 하나만 켜면 됩니다.
- **토큰으로는 프로젝트 설정을 바꾸거나 프로젝트를 보관 또는 복구할 수 없습니다.** 역할이 admin이어도 마찬가지입니다. 게이트 정책은 프로젝트 설정의 일부입니다. 토큰으로 정책을 낮출 수 있다면 게이트 면제를 받지 않고도 게이트를 피할 수 있습니다. 프로젝트를 보관하거나 복구하는 일도 그만큼 무겁습니다. 그래서 이 일들은 사람이 웹에서 직접 합니다.
- **`spec:approve`와 `approval:decide`는 토큰에 부여할 수 없습니다.** 발급 화면에서 두 권한은 **보이지만 잠겨** 있습니다. 목록에서 아예 빼 버리면 "왜 승인 권한은 토큰에 못 주지?"라는 물음의 답을 화면에서 찾을 수 없기 때문입니다. 보이지만 고를 수 없게 두면 이 규칙을 화면에서 바로 알 수 있습니다. 승인은 사람이 하는 일입니다.
- **토큰으로는 질문에 답하거나 게이트를 면제하거나 받은 요청을 읽을 수도 없습니다.** admin 역할도 예외가 아닙니다. 에이전트가 자기 질문에 스스로 답하면 사람이 지키는 게이트가 없는 것과 같기 때문입니다. 답변은 사람이 웹의 받은 요청 화면에서 합니다.
- 토큰의 권한은 역할보다 넓어질 수 없습니다. 상한은 발급할 때가 아니라 토큰을 쓸 때의 역할입니다. 나중에 역할이 바뀌면 이미 발급한 토큰에도 바로 반영됩니다.
- 목록에는 마지막 사용 시각과 마지막 호스트가 기록됩니다. 모르는 호스트가 보이면 바로 그 토큰을 폐기하세요.

## 스킬 {#skills}

| 스킬             | 하는 일                             |
| ---------------- | ----------------------------------- |
| `/nerv:next`     | 다음 작업 추천과 클레임             |
| `/nerv:spec`     | 스펙 초안·변경 요청 작성            |
| `/nerv:impl`     | 클레임한 작업의 구현 절차           |
| `/nerv:question` | 질문 올리기와 답 기다리기           |
| `/nerv:review`   | 리뷰 제출과 발견 처분               |
| `/nerv:mirror`   | 스펙 문서와 첨부를 로컬 폴더에 받기 |

`/nerv:mirror`는 다른 스킬과 달리 MCP 도구를 쓰지 않습니다. 플러그인에 든 `nerv-mirror` 스크립트가 스펙 문서와 첨부를 요청 한 번으로 내려받아 지정한 폴더를 서버와 같게 맞춥니다. 에이전트에게는 요약 몇 줄만 돌려줍니다. 기준은 **승인본**(기본) · **최신**(초안과 검토 중 포함) · **기준선** 중에서 고릅니다. 폴더에는 미러가 쓴 파일 목록(`.nerv-mirror.json`)이 남습니다. 다음에 받을 때는 그 목록에 있는 파일만 고치거나 지웁니다. 같은 폴더를 다시 받으면 지난번 기준을 그대로 씁니다. 토큰에는 `spec:read` 권한이 있어야 합니다. 스크립트를 실행하려면 node 18 이상이 필요합니다.

## 도구 티어 {#tool-tiers}

도구마다 위험 티어가 정해져 있습니다.

- **A1** — 읽기입니다. 승인 없이 호출합니다.
- **A2** — 쓰기입니다. 되돌릴 수 있는 변경만 여기에 속합니다.
- **A3** — **사람 승인이 필요합니다.** 검토 요청(`nerv_spec_submit_review`)과 에이전트가 `critical` 발견을 기각이나 유예로 처분하는 일이 여기에 속합니다. 검토 요청 도구는 어떤 스킬에서도 승인 없이 호출할 수 있는 도구 목록에 들어가지 않습니다. 에이전트가 `critical` 발견을 그렇게 처분하려고 하면 서버가 승인 카드를 만들고 세션은 사람의 결정을 기다립니다. **결정은 요청한 세션에 다음 하트비트 때 전달됩니다.** 승인, 거절, 코멘트 모두 같은 방식으로 전달됩니다. 그래서 그 세션은 이어서 무엇을 할지 알 수 있습니다.

## 문서 가져오기 {#import}

기존 저장소의 문서를 스펙과 작업으로 가져올 때는 CLI를 씁니다.

```
nerv import <spec|plan|review|docs|rebuild-map> --root <경로> --project <slug> [--apply]
```

모드는 다섯 가지입니다. `spec`, `plan`, `review`, `docs` 네 모드는 문서를 가져옵니다. `rebuild-map`은 이미 가져온 항목의 대응표를 다시 만듭니다.

**프로파일은 반드시 지정하세요.** `--profile`과 `--profile-file`을 모두 생략하면 CLI가 경고 없이 기본 프로파일을 씁니다. 다른 저장소의 규칙으로 내 문서를 읽는 셈이라 결과가 어긋나도 알아채기 어렵습니다.

`--apply`를 붙이려면 서버와 토큰을 지정해야 합니다(`--server`와 `--token`, 또는 `NERV_SERVER`와 `NERV_TOKEN`). 지정하지 않으면 명령이 거부됩니다.

`--apply` 없이 실행하면 **dry-run**으로 동작합니다. 아무것도 쓰지 않고 리포트만 출력합니다. 리포트에는 읽은 건수, 변환한 건수, **무엇을 왜 건너뛰었는지**가 줄 단위로 적힙니다. 사람이 그 리포트를 확인하고 판단한 뒤에 `--apply`를 붙여 실행합니다.

같은 명령을 다시 실행해도 안전합니다. 이미 가져온 항목은 다시 만들지 않고 비어 있던 링크만 채웁니다.
